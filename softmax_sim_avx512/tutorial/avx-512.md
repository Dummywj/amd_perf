# AVX-512 Softmax：从向量指令到通用 Uop

本文介绍项目中的 AVX-512 softmax kernel、编译器生成的主要向量指令，以及这些指令如何转换为跨 ISA 的通用 uop。相关实现位于：

- `kernel/softmax/x86/softmax_avx512.cpp`：AVX-512 intrinsic kernel；
- `kernel/softmax/artifacts/x86/softmax_avx512.s`：编译器生成的汇编；
- `recipes/x86.yaml`：x86 指令到 semantic uop 的映射；
- `uops/uop_kinds.yaml`：跨 ISA 的 semantic uop 词表；
- `profiles/amd_zen4.yaml`：semantic uop 到 Zen 4 等效 execution uop 的时序绑定。

## 1. AVX-512 基础

AVX-512 使用 512 位 `zmm` 寄存器。对 FP32 数据而言，一条 512 位指令可以同时处理：

```text
512 bit / 32 bit = 16 个 float
```

项目中的 x86 kernel 因而每次循环处理 16 个元素，并要求 `count > 0` 且 `count % 16 == 0`。这个约束使当前主路径不需要 mask 和标量尾循环。

生成的汇编采用 AT&T 语法，操作数顺序通常是：

```text
指令  源操作数1, 源操作数2, 目标操作数
```

例如：

```asm
vsubps %zmm3, %zmm2, %zmm1
```

表示逐元素计算 `%zmm1 = %zmm2 - %zmm3`。

需要注意，AVX-512 描述的是 ISA 可见的指令和寄存器宽度，不代表处理器内部一定存在一条 512 位宽的数据通路。当前 Zen 4 profile 将多数 512 位计算建模为两个 256 位等效 execution uop，但这不是对隐藏物理 uop 数量的断言。

## 2. Softmax 的三遍计算

对输入 `x[0..N-1]`，softmax 为：

```text
m    = max(x)
e[i] = exp(x[i] - m)
s    = sum(e)
y[i] = e[i] / s
```

kernel 分成三遍：

1. 最大值遍历：加载 16 个 FP32，用 `vmaxps` 累积向量最大值，最后做水平归约。
2. 指数与求和遍历：计算 `x - max`，使用多项式近似 `exp`，保存中间结果，同时累积向量和。
3. 归一化遍历：计算 `1 / sum`，重新加载中间结果，乘以倒数并写回。

三遍设计让 load、store、FMA、conversion、整数位操作和 reduction 都出现在同一 kernel 中，适合验证面向大模型推理的通用向量后端。

## 3. 项目中涉及的指令

下表按功能归纳当前编译产物中的 SIMD 指令。intrinsic 与汇编不是一一固定对应的，最终映射以实际生成的汇编和 `recipes/x86.yaml` 为准。

| 功能 | C++ intrinsic 或来源 | 典型汇编 | Semantic uop |
|---|---|---|---|
| 非对齐向量加载 | `_mm512_loadu_ps` | `vmovups memory, zmm` | `address_generation` + `vector_load` |
| 非对齐向量存储 | `_mm512_storeu_ps` | `vmovups zmm, memory` | `address_generation` + `vector_store` |
| 标量广播 | `_mm512_set1_ps` | `vbroadcastss` | `vector_broadcast`，内存源还包含地址生成和加载 |
| 整数广播 | `_mm512_set1_epi32` | `vpbroadcastd` | `vector_broadcast` |
| 最大/最小值 | `_mm512_max_ps`、`_mm512_min_ps` | `vmaxps`、`vminps` | `vector_fp_max` |
| FP32 加减乘 | `_mm512_add_ps` 等 | `vaddps`、`vsubps`、`vmulps` | `vector_fp_add/sub/mul` |
| 融合乘加/负乘加 | `_mm512_fmadd_ps`、`_mm512_fnmadd_ps` | `vfmadd132ps`、`vfnmadd132ps` | `vector_fp_fma` |
| FP32 转整数 | `_mm512_cvttps_epi32` | `vcvttps2dq` | `vector_convert` |
| 整数转 FP32 | `_mm512_cvtepi32_ps` | `vcvtdq2ps` | `vector_convert` |
| 整数加法 | `_mm512_add_epi32` | `vpaddd` | `vector_integer` |
| 整数左移 | `_mm512_slli_epi32` | `vpslld` | `vector_shift` |
| 寄存器移动 | 编译器生成 | `vmovaps` | `vector_move` |
| 向量清零 | `_mm512_setzero_ps` | `vxorps` | 当前 recipe 记为 `vector_fp_add`，profile 将零值惯用法按零延迟移动处理 |
| 水平归约展开 | `_mm512_reduce_max_ps`、`_mm512_reduce_add_ps` | `vextractf64x4`、`vextractf128`、`vpermilps`、`vshufps` | `vector_shuffle`，再配合窄宽度 add/max |
| 标量加法/除法 | 归约尾部和 `1/sum` | `vaddss`、`vdivss` | `scalar_fp_add`、`scalar_fp_div` |
| 向量状态清理 | 编译器函数尾部 | `vzeroupper` | `vector_config` |

### 3.1 带内存操作数的计算指令

x86 允许部分计算指令直接使用内存操作数。例如：

```asm
vmaxps (%rdi,%rax,4), %zmm0, %zmm0
```

ISA 层面它是一条指令，但模拟时需要表达三个不同动作：

```text
address_generation -> vector_load -> vector_fp_max
```

这样 AGU、load-data 通路和 vector-fp 通路能够分别参与资源竞争。

### 3.2 FMA

FMA 在一次指令中完成乘法和加法，并且只进行一次舍入。指数近似采用 Horner 形式：

```text
p = p * reduced + coefficient
```

因此编译器生成连续的 `vfmadd132ps`。这些指令存在数据依赖链，FMA latency 会直接影响多项式求值的关键路径。

`vfnmadd132ps` 用于计算近似的范围缩减项，本项目将 FMA 和负 FMA 都映射到 `vector_fp_fma`，具体 opcode 的时序由 profile recipe 决定。

### 3.3 Conversion 与整数位构造

指数近似把输入转换成以 2 为底的指数形式：

1. `vcvttps2dq` 将缩放后的 FP32 截断为整数指数；
2. `vcvtdq2ps` 将整数转回 FP32，用于计算余项；
3. `vpaddd` 加上 FP32 指数偏置 127；
4. `vpslld` 左移 23 位，构造 IEEE-754 指数位；
5. 将这些位按 FP32 解释，并与多项式结果相乘。

这里的整数操作不是复杂控制逻辑，而是高吞吐指数近似的一部分。

### 3.4 Reduction 为什么会产生 shuffle

AVX-512 intrinsic 提供 `_mm512_reduce_max_ps` 和 `_mm512_reduce_add_ps`，但它们不是一条对应的 AVX-512 硬件归约指令。编译器会把 16 个 lane 的水平归约展开为：

```text
512 bit -> 提取两个 256 bit 半区并合并
256 bit -> 提取两个 128 bit 半区并合并
128 bit -> permute/shuffle 后继续 add 或 max
```

因此，虽然 softmax 主循环不需要通用 shuffle，归约 lowering 仍会实际产生 `vextractf64x4`、`vextractf128`、`vpermilps` 和 `vshufps`。项目只建模这类基础归约所需的 permutation，不扩展到任意复杂 shuffle、gather/scatter 或 mask 操作。

## 4. 三层 Uop 表示

项目有意区分三种对象：

```text
x86 指令
  -> semantic uop：跨 ISA 的计算含义
  -> execution uop：某个微架构上的等效执行动作
```

### 4.1 指令

指令是 ISA 可见对象，例如 `vmaxps` 或 RVV 的 `vfmax.vv`。它包含操作数编码和寄存器规则，但不直接说明目标处理器的 latency、吞吐率或执行端口。

### 4.2 Semantic uop

`uops/uop_kinds.yaml` 定义通用语义，例如：

- `vector_load`：加载活动向量元素；
- `vector_fp_fma`：逐元素融合乘加；
- `vector_reduce_max`：最大值归约；
- `address_generation`：计算有效地址。

这一层不包含 latency、资源容量和微架构名称。同一种 semantic uop 可以来自 x86 或 RVV。

### 4.3 Execution uop

execution uop 是 profile 绑定后的调度单位，包含：

- latency；
- issue interval；
- resource occupancy；
- 可选执行资源；
- issue domain；
- 512 位操作的等效分解关系。

它服务于周期模拟。当前 profile 中的分解是有测量依据的等效模型，不应解释成真实物理 uop 的精确数量。

## 5. 转换流程

### 5.1 Intrinsic 编译为汇编

执行：

```bash
softmax_sim_avx512/kernel/softmax/scripts/build_assembly.sh
```

编译参数包含 `-O3`、`-mavx512f`、`-mavx512dq`、`-mavx512bw`、`-mavx512vl` 和 `-mfma`。模拟器输入是汇编，不进行二进制解码。

intrinsic 只表达期望的向量语义，寄存器分配、内存操作数融合和 reduction lowering 由编译器决定。因此编译器或编译参数变化后，必须重新生成并审核汇编。

### 5.2 x86 Recipe 生成 Semantic uop

`recipes/x86.yaml` 按 `mnemonic + operand form` 匹配指令。例如：

```yaml
- mnemonic: vmaxps
  form: memory_load
  uops: [address_generation, vector_load, vector_fp_max]
```

静态解析器 `src/utils/asm_to_uop.py` 会验证所有 uop 都存在于公共 catalog。遇到未知指令形式时直接报错，防止编译器变化被静默映射成错误 uop。

当前静态汇编包含 78 条指令和 108 个 semantic uop。这个数字只描述函数的静态指令体，不等于执行一次 `softmax(N)` 的动态数量。

### 5.3 动态展开与依赖

模拟器使用 `src/frontends/x86.py` 沿实际分支展开三个循环，根据 `count` 生成动态 instruction occurrence。每个实例记录：

- 标准化寄存器读写和 flags 依赖；
- 输入/输出缓冲区中的抽象地址；
- 访问字节数和 cache line；
- semantic uop；
- 稳定的动态 instruction ID。

因此 `N=256` 会生成比 78 条静态指令更多的动态实例。

### 5.4 Profile 绑定为 Execution uop

以带内存操作数的 ZMM `vmaxps` 为例，Zen 4 profile 生成：

```text
agu
  |
load
  +------> max-part-0
  +------> max-part-1
```

- `agu` 使用 `address-generation`；
- `load` 使用 `load-data`，load latency 由 cache 命中层次决定；
- 两个 max part 使用 `vector-fp`；
- 两个 part 表示 Zen 4 的 512 位操作在 256 位数据路径上的等效分解；
- 寄存器 RAW 依赖和循环依赖会继续连接到这些 execution uop。

这说明 semantic uop 用来统一 ISA，而 profile 才决定某个微架构如何执行它。

## 6. 与 RVV 的统一方式

通用 uop 不是 x86 指令的改名。例如：

| 语义 | x86 来源 | RVV 来源 | 公共 uop |
|---|---|---|---|
| 向量加载 | `vmovups` | `vle32.v` | `address_generation` + `vector_load` |
| 向量存储 | `vmovups` | `vse32.v` | `address_generation` + `vector_store` |
| FP32 FMA | `vfmadd132ps` | `vfmacc.vv` | `vector_fp_fma` |
| 最大值归约 | shuffle + `vmaxps` lowering | `vfredmax.vs` | 归约语义或其等效基本操作 |

x86 的向量长度固定为 512 位；RVV 的 `vl` 由 `vsetvli` 和运行时 VLEN 决定。这个差异由 ISA 前端和微架构 profile 处理，事件驱动后端仍只调度 execution uop。

## 7. 如何查看转换结果

从仓库根目录执行：

```bash
PYTHON=python3 softmax_sim_avx512/kernel/softmax/scripts/build_traces.sh
```

主要输出为：

- `kernel/softmax/artifacts/x86/softmax_avx512.s`：x86 汇编；
- `kernel/softmax/artifacts/x86/softmax_uops.json`：静态 semantic uop trace；
- `kernel/softmax/artifacts/x86/softmax_uops_bound.json`：静态资源绑定审计结果。

查看统计信息：

```bash
python3 - <<'PY'
import json

path = "softmax_sim_avx512/kernel/softmax/artifacts/x86/softmax_uops.json"
with open(path, encoding="utf-8") as stream:
    trace = json.load(stream)
print(json.dumps(trace["statistics"], indent=2))
PY
```

## 8. 阅读映射时的原则

1. 不把一条 ISA 指令等同于一个 uop。内存源计算可能拆成 AGU、load 和 compute。
2. 不把 semantic uop 等同于物理 uop。semantic uop 只表达跨 ISA 含义。
3. 不从 512 位寄存器宽度推断处理器内部执行宽度。执行分解必须来自 profile。
4. 不为未知指令填写默认时序。新增汇编形式应先补 recipe 和测试依据。
5. 不用 softmax 的最终周期反向随意修改已校准 profile。softmax 是综合验证负载，不是所有参数的唯一训练负载。
